## Context

0.5.0 is the launch release (task 0115).  Its README *Stability* section
says what a 0.x version promises: breaking changes are marked, saved
descriptions migrate or fail with a code, codes are stable from 0.5.0,
and meshes reproduce on the same versions and system.

1.0 is a stronger promise: **nothing breaks until 2.0.**  So the
question isn't which features are nice to have, but what must be right
before that promise is made, because after it a fix to the public
surface costs a major version.

State on 2026-11-08:
- **DESIGN §9 "Current deviations"** has four rows: shape-type switches
  outside `core.shape` and `sections` (7 sites, capped); readers in
  `io`; `n_outer = 8` (task 0088); the tee's limits (angle done in 0060;
  offset 0061 and twist 0062 open).
- **Plant fittings:** equal tees are rejected (`equal_tee_unsupported`).
  Decision 0031's amendment routes them through the **wye-layout
  redesign** (decision 0029, item 5; scope grown to asymmetric
  daughters), which has no task.  Angled tees in networks: task 0103.
  Crosses: rejected.  Insulated wyes wait on wye shells (0053's
  follow-ups) and the redesign.
- **Validation:** 11 of 12 cases accepted; the helical pipe (0075) is
  held for hardware.  MMS covers all 16 fittings for conduction (0074).
  No junction *flow* case: the Štigler T-junction benchmark (RESEARCH
  §7.2) is equal-diameter, so it waits on equal tees.  The turbulent bend
  is task 0050.
- **Distribution:** installs from GitHub
  (`pip install "hexmesh @ git+https://…@v0.5.0"`).  PyPI isn't possible
  for now: the user can't create an account with their email
  (2026-11-08).

## Options

### A. Declare 1.0 now, on 0.5.0's surface
Fast.  But equal tees, the redesign and the API review would land after
the promise, and anything they need to change in the public surface
would be a 2.0.

### B. 1.0 when the surface is complete and reviewed (recommended)
A short list of exit criteria, milestones 0.6–0.8, then 1.0 as an
unchanged 0.8 after a soak.  Slower, but the promise is made once, on a
surface that has been looked at as a whole.

### C. Feature-complete 1.0 (every proposed expansion first)
Vascular networks, pipe-in-pipe, flow restrictions, the simulation
suite.  Years, and none of it needs to change the 1.0 surface: each is
additive (their decisions' constraints).

## Decision (accepted: B)

### What 1.0 promises
1. **Semantic versioning:** breaking changes to the Python API, the
   saved-description format, the CLI's JSON (the envelope and each
   command's `result`), the manifest's format or the error codes come
   only in 2.0.  1.x adds; it never removes or renames.
2. **Deprecation before removal:** anything to be removed in 2.0 is
   deprecated, with a `DeprecationWarning` and a CHANGELOG line, for at
   least one 1.x minor release.
3. **The 0.5.0 promises, now binding:** old descriptions migrate on load
   or fail with `description_version_unsupported`; codes are only added;
   meshes are byte-identical for the same description, hexmesh version,
   gmsh version and system, and a change that moves nodes in 1.x is
   noted in the CHANGELOG.

### Exit criteria
1. **DESIGN §9 empty**, or each remaining row accepted as permanent by
   decision:
   - `n_outer = 8` as the sub-partition (task 0088);
   - the tee's offset and twist (0061, 0062);
   - the shape-switch cap falling as those land;
   - **readers out of `io`:** the deprecated `io.readers` path removed
     before 1.0 (removing it after would be breaking).
2. **The common plant fittings:**
   - **equal tees and equal laterals,** through the wye-layout redesign
     (decision 0029 item 5, decision 0031's amendment).  Choice 1.
   - angled tees from PCF (0103);
   - insulated wyes (wye shells after the redesign);
   - **crosses rejected** in 1.0 with a clear error, asked about in 1.x.
     Choice 3.
3. **Per-arc counts on `CircleShape`** (decision 0041's option C, in the
   form fixed there; the user, 2026-11-08: "per-arc count yes").  It is
   additive, but it adds a field to the description schema and a
   topology rule, so it is reviewed with the rest of the surface before
   the freeze.  Decision 0041 is amended to take C off hold.
4. **Validation of every fitting family:**
   - a junction-flow benchmark (Štigler's T-junction, on equal tees);
   - the turbulent bend (0050);
   - junction non-orthogonality predicted before meshing (0104);
   - the wall-slope question settled (0109), so the CFD guidance is
     right;
   - the helical pipe (0075): choice 2.
5. **The stable surface reviewed once, then frozen:** one API review
   task over every public name, argument and default, the description
   schema, the CLI's JSON, the manifest and the error codes.  Rename or
   deprecate in that task; after 1.0 it's 2.0 work.
   - The network document (decision 0032, stage 2) is either in the
     reviewed surface or explicitly internal (not promised) in 1.0.
6. **Distribution without PyPI:**
   - GitHub releases with the git install line, as 0.5.0;
   - a built wheel and sdist attached to each GitHub release (no
     account needed beyond GitHub), installable by URL;
   - conda-forge (its feedstocks are run through GitHub pull requests)
     as a possible later route, not a 1.0 criterion.
7. **Hints** in equipment and studies (0111).

### Not needed for 1.0
The agent plugin (decision 0040 E); Essens tags and the docs site;
vectorising the wye projection (RESEARCH §8); the future expansions
(0018, 0021, 0030, 0035).  Each is additive.

### Milestones
| Release | Content |
|---|---|
| **0.6** | Junction completeness: the wye-layout redesign with equal tees and equal laterals; 0103; 0104; 0061; 0062 |
| **0.7** | Surface and validation: per-arc counts; the junction-flow benchmark; 0050; 0109; 0088; insulated wyes; DESIGN §9 cleared |
| **0.8 (release candidate)** | The API review and freeze; deprecations removed; wheels on the release; 0111 |
| **1.0** | 0.8 unchanged after a soak (fixes only) |

**The critical path** is the wye-layout redesign: the only large,
unstarted item, and equal tees, the junction-flow benchmark and
insulated wyes all wait on it.  It gets its own decision first (decision
0029 names it; it doesn't design it).

### The choices (settled 2026-11-08, as recommended)
1. **Equal tees and laterals are in 1.0** (most plant isometrics have
   them).
2. **The helical pipe doesn't hold 1.0:** if the hardware isn't there,
   1.0 ships with the case marked in progress, documented.
3. **Crosses are rejected in 1.0,** with a clear error; asked about in
   1.x.

  benchmark's, the API review's and the wheel workflow's, written after
  acceptance and in milestone order.
- **Future expansions:**
  - **0019 (agent SDK), 0040:** helped. A frozen CLI JSON, manifest and
    codes are what agents need.
  - **0035 (pipe-in-pipe, multi-core):** per-arc counts are its stage B
    prerequisite, now in 1.0.  `n_outer = 6` stays outside 1.0
    (additive).
  - **0018 (vascular), 0021 (restrictions), 0030 (suite):** unaffected;
    the wye redesign's asymmetric daughters help 0018.
  - **The 1.0 promise constrains them all:** each must arrive additively
    in 1.x, or wait for 2.0.
