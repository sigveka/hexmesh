# 0046 — gmsh meshes; hexmesh corrects node positions and says so

- **Status:** accepted (2026-11-10, the user: "gmsh should be
  responsible for meshing since it is the trusted tool.  hexmesh is
  infrastructure on top of that", "pojection fits the philosophy just
  fine", "opt-in, with a hint to the user when it may be necessary to do
  so, go ahead and write it")
- **Date:** 2026-11-10
- **Tasks:** 0123 (the report of what hexmesh changed); 0124 (written
  nodes for `Wye`, opt-in; held); 0130 (the bend's arc placement,
  amendment 2026-11-10)

## Context

Task 0117 showed that hexmesh can write a junction's hexes itself
(decision 0043's route B3): a discrete gmsh volume of hand-placed hexes
that reuses the neighbouring transfinite surfaces' node tags passes
every gate, through `checkMesh`, on gmsh 4.12 and 4.15.  By 0043's rule
B3 would become the junction route.  That would make hexmesh a mesher
for junctions, which decision 0007 (proposed) weighs as option C,
"native realisation".

hexmesh already changes gmsh's output in two ways, both node positions
only:
- **wall projection** (decision 0029): junction wall nodes moved onto
  the exact wall after gmsh meshes them, with a per-fitting
  `projection_report` and a warning beyond `WALL_PROJECTION_WARN_MOVE`;
- **second-order wall nodes** (decisions 0029, 0034): high-order nodes
  placed on the exact wall.

The question is where the line lies, and what the user is told.

## Options

### A. gmsh does everything; no corrections
Rejects projection, so junction walls stay off the exact geometry
(decision 0029's problem returns).

### B. gmsh creates the elements; hexmesh corrects positions; exceptions opt-in and reported (chosen)

### C. hexmesh meshes where it does better (B3 as the junction default)
The 0043 rule's outcome.  hexmesh becomes responsible for element
generation in the junctions, the hardest part of the mesh.

## Decision (accepted: B)

1. **gmsh creates every element** of a default build: the hexes, their
   connectivity and the first placement of every node.
2. **hexmesh may correct node positions** onto exact geometry after gmsh
   meshes (projection, second-order wall nodes).  It never adds, removes
   or reconnects an element in a default build.
3. **Elements written by hexmesh** (route B3) are an **opt-in per
   fitting**, never a default, and never chosen silently.  The first and
   only candidate is `Wye(…, written_nodes=True)` (task 0124; held).
   The field is stored in the description like any other, so a build
   stays deterministic from its JSON (decision 0019, constraints 4 and
   5).
4. **The hint:** when a fitting misses its predicted-quality tiers on
   gmsh's path (an error, or a warning below `PREDICTED_SJ_WARN`) and
   the opt-in is *measured* to do better on that case, the error or
   warning's hint names the opt-in and says what it means ("hexmesh
   places this junction's nodes; its elements are not generated by
   gmsh").  No hint promises what hasn't been measured: until task 0124
   measures a case, no hint names the opt-in for it.
5. **The user is told, in two levels:**
   - **Corrections** are recorded, not warned: for each fitting, the
     number of nodes moved and the largest move (absolute, in local wall
     radii and in local edge lengths), in the mesh's quality report and
     in the manifest.  The record is always present, including "none".
     The existing warning for a large move stays.
   - **Written elements** are always stated: `validate()` gives a notice
     (not a warning: it isn't a fault) naming each fitting whose elements
     hexmesh writes, and the quality report and manifest carry the same
     per fitting ("N elements written by hexmesh, not generated by
     gmsh").

## Consequences

- **DESIGN §2** gains a principle 6, "gmsh meshes; hexmesh corrects",
  in this decision's words (written with this decision).
- **Decision 0007:** option C (native realisation) is closed as a
  backend; it survives only as rule 3's opt-in.  Option D (gmsh-only)
  holds for element generation.  Option B (a neutral block description)
  is untouched: it is a refactor, not a change of who meshes.
- **Decision 0031:** "users and agents never choose a layout" gains one
  exception, rule 3's opt-in.  It chooses who places the nodes; the
  layout still follows deterministically from the fields.
- **Decision 0043:** B3 is set aside as the default route (its amendment
  of this date).
- **Task 0123:** the always-present correction record and the
  written-elements notice; **task 0124:** the opt-in itself, held.
- **Future expansions:**
  - **0018 (vascular):** odd-angle bifurcations may need the opt-in;
    the hint points to it once measured.
  - **0019/0040 (agents):** the opt-in is a schema field; the hint
    carries its own error code's hint text, so an agent sees it the same
    way; the manifest records corrections and written elements.
  - **0021, 0030, 0035:** none.

## Verified vs. assumed

- **Verified:** B3's feasibility (task 0117); the existing projection
  record and warning (`hexmesh/assembly/assembler.py`, decision 0029).
- **Assumed:** that a B3 wye layout does better than the hub on some
  case (task 0124 measures; until then the opt-in isn't offered).

## Amendment (2026-11-10): rule 5 covers every node hexmesh moves

Task 0123 found a third correction its words didn't name: at `order=2`,
a bend's high-order nodes between stations are placed exactly on its
arcs (`_revolve_high_order`), wall and interior, so it reported "none"
for a bend.  The list in *Context* and rule 2 ("projection, second-order
wall nodes") gave examples, not a closed set.  Agreed with the user
(2026-11-10: "I agree"):

- **Rule 5 covers every node hexmesh moves** after gmsh places it,
  whatever the reason, wall or interior.  Each kind of correction is
  its own entry in the record, with the same fields.
- **A new correction** comes with its record entry in the same change.
- Task 0130 records the bend's arc placement.
